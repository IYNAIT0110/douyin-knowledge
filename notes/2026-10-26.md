## 三、今日补洞：README ↔ 实际产出一致性核对（首次做）

而 README 有个特殊地位：它是每次自动化执行时**唯一会被读的入场文件**，写错不会像笔记写错那样被下一次补洞发现，而是**直接带偏下一次执行**。这次核对证明担心不是多余的 —— 7 处不符，其中 3 处是 A 级。

### 3.2 核对口径

不用"通读一遍找别扭"（主观、读第三屏就会松），改成**把 README 拆成可现算的断言，逐条跑命令验**：

| 断言类型 | 验法 |
| --- | --- |
| 累计数量 | `ls notes \| grep -c` / `ls shadowing \| wc -l` |
| 百分比 | 遍历 HTML 的 `DATA` → `BANK` 现算 |
| 文件/目录清单 | `ls` 实点，比对 README 表格 |
| 引用是否断链 | 抽 README 里的 `notes/*.md` 与 `SKILL.md` 路径，逐个 `[ -f ]` |
| 脚本 flag 声明 | 到 `.py` 里 `grep` 对应字符串 |
