## 一、一句话结论

Jev 不是"另一个更强的大模型"，而是一次**目标函数的改换**：它放弃"生成人爱看的话"，改做"给出可被机器直接执行、且概率真实可信的判断"。

如果这个方向成立，AI 落地的主战场会从"聊得更好"变成"判断得更便宜、更可信"——而这恰恰是 Agent 时代真正卡脖子的地方。

## 二、先把事实摆清楚

| 项 | 事实 |
| --- | --- |
| 模型名 | **Jev** |
| 公司 | **TypeSafe AI** |
| 创始人 | **Diogo Almeida**，前 OpenAI，RLHF 与 InstructGPT/ChatGPT 的**共同发明人之一**；2024 年初离职，隐身两年 |
| 发布时间 | 2026 年 9 月 |
| 能做什么 | 只有三件事：**Noul**（是/否）、**Choice**（几个选项选一个）、**Score**（按标准打分） |
| 不能做什么 | 不聊天、不写代码、**不生成任何自然语言** |
| 训练方法 | **RLCD**（Reinforcement Learning for Calibrated Decisions，校准决策强化学习），替代他自己参与发明的 RLHF |
| 速度 | 官方称端到端 70–500ms，相对前沿模型普遍 **20–200 倍**提速（自测最高 193.6 倍） |
| 成本 | 输入 **$0.042 / 百万 token**；**输出 token 免费**（输出只有一个决策，token 数极小） |
| 自我定位 | **System One Model**（系统 1 模型），对应卡尼曼《思考，快与慢》里的"快思考" |
| 开放程度 | **未公开论文、未开放权重、未开放训练数据**；目前处于 waitlist 阶段 |

> 名字彩蛋：**Jev** 大概率取自**杰文斯悖论**（Jevons Paradox）——煤炭燃烧效率提高后，煤的总消耗反而上升。判断变得越便宜，人们不会少用，而是会在更多地方用它。**这也是理解这个模型最重要的一句话。**

## 三、为什么它会在这个时间点爆：三条线同时收口

### 3.1 技术缺口线：我们在用"写散文"的方式做"是/否"

视频给的例子是银行客服。看似简单的一步——"这个投诉该路由给哪个部门"——传统做法是让 LLM 读完文本、走完 thinking、再到 JSON output 里吐出来。

```
输入（几百 token）→ 模型生成 → 输出结构化 JSON → 我方正则/解析器抽取 → 落库
  几秒到几十秒          贵               可能格式跑偏         又要一层维护
```

问题不是"能不能做"，而是**成本结构与真实需求严重错配**：业务要的只是一个概率和一个标签，你却为它付了一次完整文本生成的钱和时间。视频里的原话是"杀鸡用牛刀"。

#### 3.1.1 先看清它跟主流方向的夹角

视频第 30–59 秒把两条路并列摆出来。整个行业在卷的是**更强的智能、更复杂的推理、能调用 Agent 去完成复杂工作任务**；而它挑的是"一个非常小的点"——

> 我们在做很多判断的时候，实际上是不需要等那么长时间，然后生成那么多 token 去消耗的。实际上就给一个大概的判断，给一个判断不同结果的概率就行了。

**"给个概率就行了"** 这五个字是整条技术路线的压缩版：别人在延长输出，它在删掉输出。

#### 3.1.2 现场演示：不是"快一点"，是两条路径的形状不同

视频第 115–132 秒给了一个画面感很强的对比。同样一个结构化输出，Jev 那边**一下就整块出来了**；传统模型还在**一个字一个字往外吐**，吐完才能拿去做判断。

这不是速度表上的差距——自回归模型必须按序把 token 排队吐完，结果才可读；决策模型是直接给出结果。作者给的归因也更狠：

> 因为 Transformer 这个整个模型的这个局限性，导致我们需要等待。

**"慢"从工程问题变成了架构问题**，意味着靠优化工程是省不掉的，只能换架构。

更隐蔽的问题是**假置信度**。让 LLM 输出 `confidence: 0.95`，本质是它预测了"听起来很有把握的 token"，背后没有任何数学校准。把它接进自动化系统，等于把风控建在一个会说漂亮话的随机数上。

### 3.2 范式线：assistance ≠ automation

Diogo 在一个多月前的演讲里点破了这件事：

> **"Today's AI is incredible at assistance, not automation."**
> （今天的 AI 极擅长"协助"，但不擅长"自动化"。）

Claude Code 再强，你还是坐在屏幕前：它写，你看；它改，你验。这仍然属于 ChatGPT 开启的**协助时代**。

真正的自动化是：**人不在场**。AI 在后台自己判断、自己执行，一天跑几十万次，你甚至永远不会看到它做了什么。

而这条路走不通的根因，Diogo 给了一个极其刻薄的答案——因为是 RLHF：**训练它的时候，我们字面意义上就把人塞进了回路里。** 模型从头到尾学的都是"什么样的回答，人更喜欢"。你既然是按"人喜欢"优化的，就别指望它能脱离人独立运行。

### 3.3 经济线：token 经济 = 用匹配场景的智能，而不是最贵的智能

视频后半段的判断很关键：**未来大概率是小模型的，前提是每个场景用与之匹配的智能就够了。**

这跟本月收藏里吴恩达访谈那条"不要在 30-40% 被 AI 自动化的部分上跟它竞争"是同一个经济逻辑的两种表述：**稀缺的不是最强的智能，而是在正确粒度上被调用的智能。**

当判断成本从"每次几美分"降到"每次几乎为零"，原先算不过账的场景会整体复活——邮件分类、日志判警、路由分发、合规初筛、Agent 每一步的合法性校验。这就是杰文斯悖论在 AI 上的映射。

## 四、RLHF vs RLCD：真正的分歧在"优化什么"

这是整段视频的技术核心，也是最容易被一带而过的地方。

| 维度 | **RLHF**（带人类反馈的强化学习） | **RLCD**（校准决策的强化学习） |
| --- | --- | --- |
| 优化目标 | 哪个回答**人更喜欢** | 这个决策**是否正确**，且**置信度是否诚实** |
| 奖励信号来源 | 人类偏好排序 | 决策对错 + 严格适当评分规则（proper scoring rule，如 Brier score） |
| 输出附带什么 | 一段（可能很好听的）自然语言 | 一个标签 + 一个**经过数学校准**的概率 |
| 副作用 | 会 drop 掉"高效但人不喜欢"的回答模式；不可信的一致性 | 放弃所有生成能力 |
| 典型失效 | 不懂装懂、"过度承诺是一种 feature" | 只会在规定的答案类型里选；仍可能选错 |
| 适配场景 | 面向人的产品 | 面向软件的自动化流水线 |

**置信度被校准，意味着什么？** 视频里那段"90% / 10%"可以翻译成一条工程规则：

> 模型说 90% 的一批判断，最终就应该**大约 90% 真的发生**。

这才让"阈值路由"从口号变成可执行的工程设计：

- 置信度 ≥ 阈值 → 自动执行，人不介入
- 置信度在灰区 → 丢给更强、更贵的大模型复核
- 置信度极低 → 转人工

一句：**真正麻烦的不是 AI 不知道，而是 AI 不知道自己不知道。**

## 五、Agent 时代：把 human-in-the-loop 从"常态"变成"异常"

视频最后落到 Agent 编排上，这是它对读者最有用的一段，值得单独拎出来。

今天跑一个 Agent，流程里塞满了人工把控环节：生成结果达标了吗？要重试吗？要不要调下一个工具？这些内容现在多半靠 **human in the loop**——人在看。所以 Agent 再聪明，人也卸不下来。

换成可校准的判断模型之后，规则可以被写死：

| 达标概率 | 动作 |
| --- | --- |
| 80% 以上 | 直接放行，不进人审队列 |
| 40%–80% | 交给更大的模型复核 |
| 40% 以下 | 转人工处理 |

**人工就从"每一步都在场"退到"只在异常时出现"。** 这是自动化能不能真正跑起来的分水岭，也是 Jev 这类模型最大的商业想象力所在。

外部信息也印证了这个方向已经在实操：有人把它接进浏览器插件按语义过滤信息流（单次判断约 380ms）、有人用它玩马里奥（一秒十次决策）、有人把它接到代码 Agent 上清理无用上下文、LangChain 在测它作为 **Agent 评估器**（判断任务到底做完没有）。

## 六、最大的那块市场不在模型层，在软件层：被取代的是分类器

这是视频 367–408 秒的一段。**回逐字稿按时间轴比对时才发现，两篇笔记此前整段没收**——而它其实是全片想象力最大的一步。

前面所有论据都还停留在"用 Jev 替掉某一次 LLM 调用"，本质是**替换**。到这一段，作者把视线抬高了：

> 接下来我们会看到，**每一个软件背后可能都有一套决策模型在支持**。

而它对比的对象也不是大模型，是**分类器**：

| | 以前 | 现在 |
| --- | --- | --- |
| 怎么来的 | 人先攒数据、训练一个分类器，调半天 | 直接让这个模型判断 |
| 判断依据 | 训练时见过什么，就认什么 | 按**情境**判断特定的结果 |
| 门槛 | 要数据、要训练、要持续维护 | 一次 API 调用 |

作者的原话很干脆："我们叫训练一个分类器……**但是现在不需要了**。"

这一步的意义在于：当判断的成本降到接近零，AI 就不再是一个"你主动打开去用的东西"，而是**被烧进软件的一道默认工序**——

> 相当于智能就已经融合到更多的软件中，一些决策场景中，我们更多的这种应用中，会看到越来越多这样的能力的扩散。

**从"调用 AI"到"软件自带判断"，是量级上的差别。** 前者是你在某个环节想起了 AI；后者是每一个界面、每一次点击、每一条日志背后都悄悄多了一次判断，你甚至不知道它在。这也正是杰文斯悖论在软件层的具体形态：不是"AI 用得更省了"，而是"AI 出现在了原先根本不会考虑它的地方"。

顺带说一句：被替换的那批东西，今天多半长着**根本不像 AI 的样子**——正则、关键词黑名单、if-else 规则树、人工维护的规则引擎。它们从来没被算进"AI 能做什么"的账里，恰恰因此是最先被换掉、也最容易被忘掉的一批。

## 七、边界与反方：别急着把它封神

写笔记的人有责任把话说完整。目前至少有四条明确的保留意见：

1. **数据全是自测。** 193.6 倍、444.6 倍来自 TypeSafe 自己公布的测试，没有第三方复现。
2. **没论文、没权重、没训练数据。** 作为对比，已有研究者（Adil Sadqi）拿出 2025 年 3 月和 9 月的两篇 arXiv 论文与开源权重，声称同一套非自回归决策思路早做了一年，并且延迟只有 33–38ms、完全开源。**学术优先权存在争议。**
3. **"零幻觉"是有引号的。** 它保证的是**不会跳出规定的答案类型乱编**，不等于不会判断错。选择错误依然存在。
4. **它不是通用替代品。** Jev 抢的是"高频小判断"这一层；复杂的深思熟虑仍然属于大模型。把两者混为一谈，就会得出"CEO 要被一个 70ms 的分类器取代"这种蠢结论。

## 八、给我自己的落地清单

按"先做什么最划算"排序：

1. **盘点工作里的"伪生成"环节** —— 找出那些"其实只需要一个是/否、一个标签、一个分数"却在调用完整 LLM 的地方。这是最容易立刻降本增速度的一刀。
2. **给自己的 Agent 加一层置信度闸门** —— 不要每一步都让人审。先写死达标条件，让模型输出的概率真正替你分流。哪怕是先用主模型"自报 confidence + 抽样人工校验"逼自己也行，把规则先建立起来。
3. **建立"便宜判断 vs 昂贵推理"的分层预算意識** —— 每次调用前问一句：这一步是需要**想明白**，还是只需要**做判断**？两者单价差着两个数量级。
4. **盯着置信度校准这件事本身** —— 哪怕最后不用 Jev，"你所输出的概率是否可信"也是所有 AI 自动化系统迟早要回答的问题。可以去看一眼 strictly proper scoring rule / Brier score 是什么，成本不到半小时，收益长期。
5. **留意杰文斯悖论式的机会** —— 当某样东西便宜 100 倍时，**新的机会不在"原来的用法更省"，而在"原来做不起的用法"**。每一次日志、每一次工具调用、每一个网页按钮背后加一次 AI 判断，这才是量级上的变化。
6. **去数一遍你软件里那些"手搓分类器"** —— 正则、关键词黑名单、if-else 规则树、人工维护的规则引擎。它们是判断成本归零之后最先被替换的一批，也最容易被漏掉，因为它们看起来根本不像 AI 的活。
